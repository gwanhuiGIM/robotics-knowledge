# 게시 경로를 "공유 링크 → Claude 추출"로 바꾸고 GPT 전용 부분 걷어 내기

작성 2026-11-18 12:55 · 상태: 계획(승인 대기)

## 배경
- 사용자 결정(2026-11-18): 저장소 구조는 유지하고, ChatGPT가 직접 올리는 경로 대신 Claude가 답변 공유 링크에서 원문을 추출해 올린다(사용자 "q3o", 그 전 "직접 올리는데 원문보존이 안된다는 뜻 아닌지").
- 근거: GPT 직접 게시 3건 중 그림이 많은 1건(11-16 경로계획)에서 문장 2개·인라인 코드 6곳·SVG 5개가 빠지고 그림이 흐름도로 바뀜. 링크 추출 1건(11-18 멀티스레딩, a7a9f04)은 본문 줄 누락 0, 그림 4개 SVG 원본, 차트 데이터·코드는 페이지의 위젯 JSON에서 얻음.
- 링크 방식의 한계(1건 기준): 공유 링크에 사용자 질문이 없다 → 질문 원문은 사용자에게 받는다. 차트는 표로만 보인다. 카드 레이아웃 원문 태그는 없어 화면 DOM을 보고 다시 배치한다. 본문 사본은 코드 빈 줄을 잃을 수 있어 코드는 위젯 JSON을 기준으로 한다.

## 할 일
1. `tools/import_share.py <공유 링크> <slug>` — playwright(설치된 Chrome)로 공유 페이지를 열어
   - 본문 사본(`data-octane-input` JSON의 `messages[0].content`)에서 앞의 "Log in to view this content."와 끝의 후속 질문 제안 목록을 뺀 초안 md를 만든다.
   - `<img src="data:image/svg+xml…">`을 `assets/img/<slug>/figN.svg`로 저장하고 `currentColor`를 밝은 회색으로 바꾼다. 그림 위치는 직전 텍스트로 찾아 초안에 `![…](…)`를 넣는다.
   - 위젯 JSON(`client_defined_widget`)의 code_block으로 코드 fence를 덮어쓰고, visualization은 `<Chart content={…}/>` 블록으로 넣는다.
   - 카드(`data-d-component="box"` 등)는 자동 변환하지 않고 위치와 글자만 표시해 손으로 배치하게 한다.
   - 끝에 원문 줄 포함 검사와 화면 순서 대조(공유 페이지 vs 빌드 결과, 이번에 쓴 방식)를 출력한다.
2. 문서 정리: AGENTS 규칙 1(게시 요청 경로), AUTHORING 2절(connector 규칙 → 링크 추출 절차)·8절(GPT 지시문), OPERATIONS 입력 경로, state.md "사이트 의도". connector는 사용자가 정한 대로 남기거나 지운다(아래 Q).
3. 검증: 멀티스레딩 글을 스크립트로 다시 만들어 a7a9f04와 비교(카드 부분 제외 일치), 경로계획 공유 링크로도 1회 실행해 그림 위치가 현재 글과 같은지 확인.
