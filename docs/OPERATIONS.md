# Robotics Knowledge Lab — 프로젝트 경위, 운영 절차 및 에이전트 인수인계

**작성 목적:** 이후 Codex, ChatGPT Work, Claude Code 및 다른 에이전트가 과거 대화 맥락 없이 저장소를 안전하게 운영할 수 있게 한다. 본 문서는 사용자가 이 프로젝트에서 지시한 목적·공개된 개발 이력의 요약이며, **채팅 전문 복제본이 아니다.** 확정된 구현과 향후 권장 설계를 구분한다.

## 1. 제품 목표 및 우선순위

로보틱스 관련 ChatGPT 학습 대화를 누적해 검색·열람하는 정적 지식 아카이브.

1. **최상위 요구:** 사용자 질문과 해당 GPT 답변 **전문 보존**, Q1/A1... 순서, 코드·표·수식·출처·이미지 등의 정보 보존.
2. 그다음: 실제 게시된 글만 공개, 주제 분류 및 키워드 검색, 긴 글의 탐색/가독성.
3. 그다음: 다크 테마, 반응형, 자동화 및 지속적 유지관리.
4. 검증하지 못한 역사/원문/작동 상태는 추정하지 않는다.

- GitHub: https://github.com/gwanhuiGIM/robotics-knowledge
- Pages: https://gwanhuigim.github.io/robotics-knowledge/
- 주로 한국어로 답변하며 ROS 2, AI, 임베디드 로봇, 시뮬레이션, 스마트팩토리 등을 다룬다.

## 2. 웹사이트와 운영 방식이 정해진 경위

아래는 프로젝트 대화에서 합의/요청한 변화의 **작업 경위 요약**이다. 원문 대화 전체가 GitHub에 들어 있다는 주장은 하지 않는다.

- 초기에 가상 프로토타입/예시 카드가 포함된 웹 UI가 있었다. 사용자는 **실제로 업로드한 학습 자료만 보여 주되 기존 사이드바 분류와 검색을 유지**하도록 요구했다.
- 사용자는 ChatGPT 공유 URL만으로 전체 답변/이미지 재현이 어려울 수 있음을 확인했고, 그래서 **대화 전문을 붙여넣거나 파일로 제공**했다. 공유 URL 접근이 가능하지 않을 때 과거 원문을 추측하지 말 것.
- 게시한 주제에는 Omniverse 실무 경험, 로봇 팔 jitter, Linux RT/RTOS, DevOps·CI/CD, 엣지 컴퓨팅 분산 아키텍처(연속 질문 3개), MES가 있다. 개별 문서의 provenance/원문 확보 여부는 각각 확인한다.
- 사용자는 긴 답변에서 **스크롤 고정 목차, 뒤로가기, 맨 위로, 본문 타이포그래피, 모바일 화면**을 요구했다. 공통 `assets/reader.css`와 `assets/reader.js`를 도입했다.
- 독립 감사에서 검색/분류의 숨김 오류, Edge 세부 heading 누락, 비교표·차트 평탄화, 링크 누락, 카드 개수 하드코딩, 모바일 표 오버플로 가능성을 지적했다. 이후 CSS/JS 및 Edge/MES 콘텐츠를 보완했다. **수정 커밋이 브라우저 회귀 검사 통과를 자동 보증하지는 않는다.**
- 장기적으로 ChatGPT 프로젝트 직접 요청과 Notion 게시 요청을 병행하고, GitHub에 근거와 작업 규칙을 남겨 다른 에이전트가 유지보수할 수 있게 했다.

## 3. 두 가지 게시 입력 경로

### A. ChatGPT 프로젝트 대화 — 즉시 게시

사용자가 `Robotics Domain Knowledge` 프로젝트 채팅에서 **'사이트에 게시해줘'** 같이 명시적으로 요청할 경우, 그 대화에 실제로 제공된 질문/답변 또는 파일을 기준으로 즉시 문서를 작성하고 GitHub에 게시한다. 새 질문만 주면서 게시를 요청했다면 완전한 **신규 GPT 설명**을 먼저 생성해 게시할 수 있다.

- 단순 지식 질문만으로 공개 게시하지 않는다.
- 과거 다른 ChatGPT 세션의 원문을 아무 도구 없이 전부 가져올 수 있다고 가정하지 않는다.
- 과거 답변의 정확한 복제를 원한다면 원문 텍스트나 파일이 필요하다.

### B. Notion Idea Inbox — 예약 처리

Notion 데이터 소스: `collection://521e88fc-56fa-40a4-9e5f-0b480c89ffb1`
Notion UI: https://app.notion.com/p/c95a3920ae29491cb969c4622ed2aedb

기존 `Notion Idea Research` 작업을 **`Robotics Knowledge Lab 게시 자동화`**로 변경했다.
- 자동화 ID: `6a95f0a1d2048191b0cdc1f9aa03eedd`
- 예약 시간: **한국 시간 00:00 / 12:00 / 15:00 / 18:00**, 실행당 게시 시도 최대 5건
- 기존 Notion DB에는 `제목`, `입력 내용`, `URL`, `상태`, `우선순위`, `처리 모드`, `분석 페이지` 등의 속성이 있다. **'게시 대기'라는 Notion 상태 옵션이 실제로 있다고 가정하지 말 것.**
- 가장 간단한 입력: 새 페이지 제목에 **`사이트 게시 | ROS 2 QoS의 Reliability와 Durability 차이`**. 다른 속성은 비워도 처리 대상으로 삼도록 예약 지시문이 설정되었다.
- `입력 내용`이나 페이지 본문에 필요한 깊이, 예시, 대상 기술을 추가할 수 있다.
- **신규 생성 모드:** 질문/주제만 전달된 경우 새 한국어 답변을 작성하고, '새로 생성한 답변'임을 표시.
- **기존 답변 보존 모드:** `기존 GPT 답변 원문 게시` 의도인 경우 Q&A 전문을 실제 확보한 뒤 게시. 원문 미확보면 확인 필요.
- 정상 처리는 기존 상태 선택지 `완료`를 사용하고, `분석 페이지`에 실제 사이트 글 URL을 기록. 원문 입력 필드 덮어쓰기 금지. 권한·출처·개인정보 문제가 있으면 `확인 필요`.
- Notion 댓글·전체 DB 조회·원문 접근은 매 실행의 **실제 제공된 도구 권한**에 종속된다. 위 내용은 **예약 지시문 설정**이며 Notion→GPT→GitHub 전체 자동 게시의 종단간 성공이 검증됐다는 뜻이 아니다.
- 예약이 모든 ChatGPT 프로젝트 채팅을 백그라운드에서 읽는 것은 아니다. 프로젝트 직접 요청은 해당 채팅에서 즉시 처리한다.

### 예약 실행 흐름

`Notion 명시적 게시 요청 → 항목/본문 읽기 → 공개 안전성/중복 확인 → 답변 생성 또는 원문 확보 → Q&A 페이지 제작 → GitHub 커밋 및 홈 등록 → 코드/배포 확인 → Notion 원본 항목에 결과 기록`

기존 아이디어 연구/모니터링 항목은 **별도 게시 요청 없으면 임의 업로드하지 않는다**.

## 4. 소스 원문과 표시 문서의 구분

반드시 이 두 가지 모드를 구분한다.

| 항목 | 기존 GPT 답변 보존 | 질문만 받고 새로 생성 |
| --- | --- | --- |
| 질문 | 제공된 사용자 질문 그대로 | 제공된 질문 그대로 |
| 답변 | 실제 확보한 GPT 답변 전문, 수정·삭제 없이 | 새로 작성한 설명, 별도 표시 |
| 추가 시각화 | 원본과 구분하여 재구성 표시 | 출처와 새 제작 표시 |
| 불명확한 출처 | 확인할 수 없음을 기재 | 검증 가능한 링크만 사용 |
| 오류·정정 | 원문을 덮어쓰지 않고 주석/별도 정정 | 최신 근거로 작성하고 검증 여부 표시 |

외부 이미지의 무단 재게시 금지. 첨부된 텍스트 추출물의 표가 평탄화된 경우, **확실한 열·행만** 복원하며 불명확하면 원문 텍스트를 같이 보존한다.

## 5. 현재 파일 기준 구현

저장소를 실시간 조회해 구조를 확인한 후 작업한다. 현재 알려진 경로:

- `index.html`: 게시 카드 목록, 카테고리 버튼, 검색, 자료 수
- `articles/*.html`: 개별 문서 (기존 각자 스타일을 포함할 수 있음)
- `assets/reader.css`, `assets/reader.js`: 전체 문서에 적용하는 공통 리더 UI
- `.github/workflows/static.yml`: `main` push시 GitHub Pages 배포

**주의:** `content/*.md`, `metadata.json`, CI 테스트 파이프라인, 서버 DB 등은 장기적 개선 제안이지 현재 존재한다고 보장하지 않는다. 별도 승인 없이 전체 구조를 전면 교체하지 말 것.

## 6. 게시/수정 절차 (에이전트 SOP)

1. 게시 의도를 확인하고 제목·질문·원문·출처·개인정보를 점검한다.
2. 이미 같은 주제/Notion page id/원문이 게시됐는지 확인한다.
3. 원문 출처와 신규 작성 범위를 구분하고, 원문 전체를 확보한다.
4. 현재 `articles/` 문서 구조 및 공통 reader asset을 참조해 HTML 콘텐츠 생성. 긴 글은 의미 있는 `h2/h3` 구조를 사용하고 누락 없는 목차가 나오게 한다.
5. 표는 `table` 구조와 좁은 화면 내부 스크롤을 사용. 코드·수식·그림 정보 보존.
6. `index.html`의 적합한 카테고리 카드에 정확히 하나 추가. 검색 키워드 포함. 기존 필터가 깨지지 않아야 한다.
7. 전체 diff를 검토한다. 기존 게시물 또는 CSS를 불필요하게 다시 쓰지 않는다.
8. GitHub write 응답의 커밋 SHA를 보존한다.
9. 가능한 환경에서 실제 Pages 접속·GitHub Actions 성공과 검색/목차/모바일 동작을 검증한다. 코드 존재만으로 동작을 단정하지 않는다.
10. Notion 요청이었으면 원본 노트에 게시 URL·SHA·처리 결과를 기록. 사용자에게 결과와 미검증 부분을 명확히 전달한다.

## 7. 감사 발견 및 회귀검사 기준

독립 감사 보고서(사용자가 채팅에서 제공, 2026-10-29 기준)의 핵심:

- **F01 / High:** `.article{display:block}`이 HTML `hidden`을 무시하게 만들 수 있음. `[hidden]{display:none!important}` 또는 동등한 우선순위 확보. **검색 무일치, Embodied AI 빈 분류, 검색+분류 복합 조건 확인.**
- **F02 / Medium:** 엣지 문서의 세부 제목 19개가 `div.heading`이었기에 `h2,h3` 기반 자동 목차에서 빠짐. 실제 의미 제목을 semantic heading으로 유지.
- **F03 / Medium:** 엣지 비교표와 전송량 차트가 단순 텍스트로 평탄화됨. 표의 열 관계, 가정 및 수치 검토.
- **F04 / Medium:** 출처 이름만 있고 URL이 없어 추적 어려움. 검증된 공식 출처 연결. 새로 찾은 자료와 원본 인용 구분.
- **F05 / Low:** 홈 게시물 수 하드코딩. 실제 카드 수를 동적으로 계산.
- **C01 / 미확정:** 좁은 화면에서 table min-width 때문에 전체 가로 스크롤 가능. 표 래퍼 및 360px·390px 테스트.

배포 전 최소 테스트:
- 분류 `all`, `Simulation`, `Control`, `Embodied AI`, `Systems`에서 카드 수·숨김 동작
- 존재하지 않는 검색어와 실제 키워드
- 각 글의 목차 앵커 존재, 클릭 후 정상 스크롤, active 항목
- 360 / 390 / 760 / 1366 px 폭에서 콘텐츠 넘침, 모바일 목차/뒤로/맨 위로
- 원문과 게시 텍스트의 누락·순서·주요 표/코드 비교
- 링크·출처 및 구분 라벨 확인
- Actions 배포 성공과 실제 웹페이지 정상 로딩은 별도 확인

## 8. 향후 개선 방향 (아직 마이그레이션 아님)

- 원문 Markdown 또는 텍스트를 `content/<slug>/original.md`로, 메타데이터를 별도 파일로 저장하는 구조.
- 공통 페이지 템플릿과 콘텐츠 빌드 스크립트, 인덱스 자동 생성.
- GitHub Actions 최소 회귀 테스트/링크 검사/콘텐츠 완전성 검사.
- 문서 분류/태그/연관 지식 링크 및 이후 규모 증가시 전문 검색.
- 대규모 구조 변경은 백업/비파괴적 마이그레이션과 테스트 후 수행.

## 9. 에이전트 협업 규약

- Codex/다른 에이전트는 먼저 `AGENTS.md`와 이 문서를 읽고, **현재 저장소 코드/설정**을 재확인한다.
- '현황 조사/감사' 요청만 받았다면 읽기/분석만 수행하고 GitHub에 임의 커밋하지 않는다.
- 실 작업 요청은 최소 단위로 수정하고 명확한 커밋을 남긴다.
- 작성 에이전트와 감사 에이전트를 가능하면 분리한다. 감사는 원문 충실성/회귀 기능/배포 증거를 확인한다.
- 검증 못한 기능은 '미검증'으로 정직하게 기록한다.
- 에이전트에게 공유하는 운영 문서에는 개인 메일, 토큰, 내부 비공개 자료를 수록하지 않는다.
