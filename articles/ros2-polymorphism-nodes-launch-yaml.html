ROS2의 Node·Launch·YAML은 다형성인가?

Python·C++의 다형성 개념에서 출발해, ROS2 노드의 교체 가능성·Launch 실행 구성·YAML 파라미터 관리가 각각 어떤 소프트웨어 설계 개념인지 구분한다.

사용자 질문 원문

로보틱스 sw 분야에, 다향성 활용 부분에 대해 설명. 파이썬 및 c++ 구체적 예시도 들어줘

ros2의 노드 개념이 다형성의 일종이라고 볼 수 있다던데 맞는지? 또한 launch파일 구성으로 노드 실행들을 묶기, yaml로 파라미터 추출 등도 다형성의 일종인지

원문 질문 2개를 보존했다. 아래는 이 대화의 답변을 통합·보완하여 재구성한 학습 문서로, 과거 답변 전문을 그대로 전사한 자료는 아니다. 코드 중 함수와 패키지 이름 일부는 예시이며 실기기 동작을 검증한 것은 아니다.

1. 핵심 결론: 교체 가능성이 곧 다형성은 아니다

ROS2 Node, Launch 파일, YAML 파라미터 파일 자체는 객체지향 다형성이 아니다. 서로 다른 구현체가 동일한 인터페이스에 따라 호출될 때 다형성이 성립한다. 독립 노드가 같은 토픽 메시지를 주고받는 구조는 인터페이스 호환성에 따른 교체 가능성을 제공하지만, 반드시 상속이나 동적 디스패치가 필요한 것은 아니다.

구성요소관련 설계 개념다형성 여부
ROS2 Node모듈화·컴포넌트/분산 시스템 설계그 자체로는 아님
Topic / Service / Action메시지 기반 통신·인터페이스 계약·느슨한 결합그 자체로는 아님
Launch프로세스/노드 실행 오케스트레이션·구성 관리아님
YAML 파라미터설정 외부화·파라미터화아님
Python ABC/override, C++ virtual/override동일 인터페이스에 대한 다중 구현·동적 디스패치맞음
pluginlib + 공통 기반 인터페이스플러그인·객체지향 다형성구현 구조에 따라 맞음

2. Python과 C++에서의 실제 다형성

ERP42 경로 추종에서 Pure Pursuit와 Stanley를 바꿔 실행한다고 가정하자. 공통 calculate_steering() 계약을 제공하면 상위 시스템은 특정 알고리즘 종류를 몰라도 호출할 수 있다.

Python: 추상 기반 클래스(ABC)와 오버라이딩

from abc import ABC, abstractmethod

class PathController(ABC):
    @abstractmethod
    def calculate_steering(self, state, path):
        pass

class PurePursuit(PathController):
    def calculate_steering(self, state, path):
        return pure_pursuit_algorithm(state, path)

class Stanley(PathController):
    def calculate_steering(self, state, path):
        return stanley_algorithm(state, path)

# 상위 시스템은 구체적 알고리즘을 몰라도 된다.
def drive(controller: PathController, state, path):
    return controller.calculate_steering(state, path)

pure_pursuit_algorithm(), stanley_algorithm()은 실제 알고리즘 구현을 연결할 자리표시자 함수다.

C++: virtual, 순수 가상 함수, override

class PathController {
public:
    virtual ~PathController() = default;
    virtual double calculateSteering() = 0;
};

class PurePursuit : public PathController {
public:
    double calculateSteering() override { return 0.1; }
};

class Stanley : public PathController {
public:
    double calculateSteering() override { return 0.2; }
};

// 공통 인터페이스를 통한 동적 디스패치
double control(PathController& controller) {
    return controller.calculateSteering();
}

C++에서 virtual은 기반 클래스 참조·포인터를 통한 런타임 디스패치에 핵심이다. override는 정확한 재정의를 컴파일러가 검사하게 한다. C++에는 함수 오버로딩·템플릿 등 컴파일타임 다형성도 있다.

3. ROS2 Node의 인터페이스 호환성과 다형성 구분

/waypoints_path
경로 입력

→
공통 조향 메시지
ERP42 Control

개념도: 두 제어 노드를 동시에 같은 최종 제어 토픽에 연결하면 명령이 충돌할 수 있다. 선택 실행·중재 노드·토픽 리매핑 등이 필요하다.

서로 다른 노드가 같은 토픽 이름과 메시지 타입을 사용하도록 설계하면 노드 단위 교체가 가능하다. 그러나 토픽 타입이 같아도 제어 의미·좌표계·주기·QoS·안전 조건까지 같다고 보장되지는 않는다. 이 구조는 객체지향 다형성과 유사한 목표를 가지지만 인터페이스 기반의 느슨한 결합이라고 설명하는 편이 정확하다.

4. Launch: 실행 오케스트레이션

Launch는 다중 노드의 실행, 네임스페이스, 인수, 파라미터, 리매핑 등을 묶어 배포·실행 구성을 관리한다. 노드를 한 파일에서 실행한다고 다형성이 생기지는 않는다.

from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        Node(package="robot_pkg", executable="camera_node"),
        Node(package="robot_pkg", executable="yolo_node"),
        Node(package="robot_pkg", executable="control_node"),
    ])

이는 모듈화된 노드의 실행 조합을 관리하는 단계다. 코드 구현과 시스템 실행 구성을 분리한다는 점에서 관심사의 분리에도 도움이 된다.

5. YAML: 설정 외부화, 다형성과의 결합

YAML로 제어기의 lookahead, 속도, 선택 알고리즘을 분리하면 소스코드를 편집하지 않고 실행 설정을 바꿀 수 있다.

path_controller:
  ros__parameters:
    lookahead_distance: 2.5
    max_speed: 5.0
    controller_type: "pure_pursuit"

이후 코드에서 설정을 읽고 공통 인터페이스를 구현한 클래스를 선택하면 설정 외부화 + 다형성 + 전략 패턴이 결합된다.

# self는 ROS2 Node 인스턴스라고 가정
self.declare_parameter("controller_type", "pure_pursuit")
name = self.get_parameter("controller_type").value
controllers = {"pure_pursuit": PurePursuit, "stanley": Stanley}
self.controller = controllers[name]()  # 생성 시점 선택
# 두 구현이 같은 calculate_steering() 계약을 충족해야 한다.

여기서 YAML은 무엇을 선택할지 지정하고, 클래스의 공통 메서드 계약은 선택된 구현체를 어떻게 호출할지 결정한다. 설정을 바꾼다고 이미 실행 중인 객체가 자동 교체되는 것은 아니다. 이를 원한다면 별도의 런타임 전환 로직과 안전 절차가 필요하다.

6. 로보틱스 프레임워크 실무 연결

  • Nav2 Controller 플러그인: 공통 Controller 인터페이스를 통해 DWB와 Regulated Pure Pursuit 등의 구현체를 선택한다.
  • ros2_control: 공통 하드웨어/컨트롤러 인터페이스와 플러그인 구조를 활용한다.
  • Composable Nodes: 여러 노드를 하나의 프로세스에 구성할 수 있지만 Composition 자체는 다형성과 다르다.
  • 센서 추상화: RealSense/USB 카메라 구현을 공통 Frame 인터페이스 아래에 둘 수 있다. 영상 포맷·타임스탬프·좌표계 등 계약까지 정해야 안정적으로 교체된다.
