Linux RT / RTOS: 로봇 실시간 제어 기초

원본 질문 및 답변 이력

질문 원문: 현재 접근 가능한 프로젝트 기록에서 이 주제의 전체 사용자 프롬프트를 확인하지 못했습니다. 원문을 임의로 만들어 넣지 않았습니다.

게시 내용: 아래는 이전 답변을 그대로 복사한 것이 아니라, 해당 기술 주제로 새로 작성한 교육용 요약입니다. 질문·답변 원문이 확보되면 그 내용을 우선하여 교체합니다.

실시간 시스템은 작업의 평균 처리 속도뿐 아니라, 지정된 시간 한계 내에 응답할 수 있는지를 중요하게 평가합니다.

1. 핵심 용어

  • Deadline: 작업 완료가 요구되는 시간 한계
  • Latency: 이벤트 발생과 실제 처리 시작까지의 지연
  • Jitter: 실행 주기 또는 지연 시간의 변동
  • PREEMPT_RT: Linux 커널의 선점 가능성을 높여 최악 지연을 줄이기 위한 실시간 패치 집합

PREEMPT_RT를 사용해도 모든 데드라인의 충족이 자동으로 보장되지는 않습니다. HW/드라이버/스케줄링/부하 시험이 필요합니다.

2. ROS 2 제어 루프 예시

기능 관계를 단순화한 개념도입니다. 실제 Controller Manager와 하드웨어 인터페이스 연결은 구성에 따라 다릅니다.

3. 주기 변동의 개념

기준 주기 1ms를 만족하는지와 별개로 Worst-case latency, 각종 부하 조건 및 스케줄링 정책을 측정해야 합니다.

4. 실무 연계 역량

  • 스레드 우선순위와 CPU affinity 설정
  • cyclictest 등 지연 시험 도구 활용
  • ROS 2 Controller Manager 제어 주기 관찰
  • 현장 장비의 안전 회로와 Linux RT의 책임 범위 구분
